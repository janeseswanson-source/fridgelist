# CLAUDE.md — FridgeList (working name)

A shared household grocery list for Turkey, Saudi Arabia and the UAE. Monorepo: a Firebase backend, a native Android app and a native iOS app that all follow one data contract.

**Read before any work:** `docs/PRODUCT_SPEC.md`, `docs/ARCHITECTURE.md`, `docs/CONTRACT.md`. Log progress in `docs/PROGRESS.md`.

## Repo map

```

android/    native Android app (Kotlin, Compose, Glance)
ios/        native iOS app (Swift, SwiftUI, WidgetKit), generated by XcodeGen from ios/project.yml
docs/       product spec, architecture, contract, progress log, runbook, store and review notes
fixtures/   shared test data used by all three codebases
prompts/    the prompts that started each workstream
```

## Golden rules

1. **The contract is law.** Field names, enums, payloads and links match `docs/CONTRACT.md` exactly. To change it: same commit updates CONTRACT.md, bumps `CONTRACT_VERSION`, adds a changelog line, and adds a note under "Contract changes for other platforms" in PROGRESS.md.
2. **Offline-first.** Every write a user makes must work offline and sync later. Network-only features (parsing, meals, guest links) need an offline fallback or a clear message, never a blocked add.
3. **Arabic first.** Build and check every screen in Arabic (RTL) before Turkish and English. No hard-coded strings. Use start/end (leading/trailing), never left/right. Format numbers with the user's locale.
4. **Privacy.** Location stays on the device; the server only learns "trip started at store X". No item, household or member names in analytics, logs or crash reports.
5. **No secrets in apps or the repo.** Apps hold only Firebase config files, which stay out of public repos. Server secrets use `defineSecret`.
6. **Shared logic stays in sync.** Normalization, the local splitter, units, the display rule and category order exist in TypeScript, Kotlin and Swift. All three must pass `fixtures/`. If you change behaviour, change the fixtures in the same commit and note it in PROGRESS.md.
7. **Small, tested steps.** One milestone at a time; plan first; tests with the code; files under about 400 lines.
8. **Stop for humans.** Console clicks, signing, paid services, store listings and legal text need the owner. Give exact steps and wait.

## Commands

| Area | Command |
| --- | --- |
| Backend checks | `cd backend/functions && npm ci && npm run lint && npm run typecheck && npm test` |
| Emulators | `cd backend && npm run emulators` (seeds demo data) |
| Android | `cd android && ./gradlew lint testDevDebugUnitTest assembleDevDebug` |
| iOS | `cd ios && xcodegen generate && xcodebuild test -scheme FridgeList -destination 'platform=iOS Simulator,name=<device>'` — pick `<device>` from `xcrun simctl list devices available` |

## Definition of done (every milestone)

- Builds, lint is clean, tests pass, and you show the test output.
- Writes work offline where the milestone touches data.
- Apps: screens checked in Arabic, Turkish and English, light and dark.
- `docs/PROGRESS.md` updated: shipped, next, open questions, contract changes.
- One commit for the milestone with a clear message.

## Emulator mode

Debug builds point at the Firebase Emulator Suite (Android emulator: `10.0.2.2`; iOS simulator: `localhost`; a physical phone: the dev machine's LAN IP from a setting). Release builds never use emulators.
