## Milestones

### I1 — Scaffold
- `project.yml` with the app, the widget extension, the `FridgeKit` package and test targets; entitlements; Info.plist keys; String Catalogs (`Localizable`, `InfoPlist`, `AppShortcuts`) for en/ar/tr.
- `FridgeKit`: CONTRACT models (Codable), display rule, normalize, units and local splitter passing every `split`-tagged case in `fixtures/parse_cases.json` for item count.
- Emulator wiring in Debug (host from a dev setting, default `localhost`).
- Done when: `xcodegen generate` and `xcodebuild test` pass; the app launches to an empty home screen in ar/tr/en.

### I2 — Sign-in, onboarding, household
- Sign in with Apple and Google → Firebase Auth, with `Auth.auth().useUserAccessGroup(...)` so the widget extension shares the session.
- Flow: sign in → display name and item language (ar, tr, en, fil, hi, ur) → create or join a household (code, QR scan, `/join/` universal link) → notification permission with a rationale screen first. UI language follows iOS; offer a button to the app's page in Settings.
- `deviceId` in the Keychain; write `users/{uid}/devices/{deviceId}` with the FCM token; observe `Activity<ShoppingAttributes>.pushToStartTokenUpdates` and save `apnsPushToStartToken`.
- Members screen with roles; owner and adults can invite (link, code, QR).
- Done when: two simulator users create and join one household and see each other with the right roles.

### I3 — Lists and items, offline-first
- Lists; list detail grouped by category in the default order (CONTRACT §2); rows use the display rule with the original underneath when different; quantity, unit, urgent flag, "asked by" avatars.
- Swipe actions: claim, done, couldn't find, edit, delete — each with undo. Kids' items in a "Requests" section for adults.
- Add sheet (text): local split shows chips at once → `parseItems` refines them online → confirm → write with `addedVia: app_text`. Ambiguous chips (confidence < 0.6) offer the alternatives and save the choice as a household alias.
- Firestore persistent cache. `SnapshotService` writes the CONTRACT §7 snapshot to the App Group (debounced 1 s) and reloads widget timelines (throttled).
- Done when: in airplane mode you can add, tick, undo and delete; back online, categories and translations arrive and the UI updates. Cover it with an XCUITest against the emulators.

### I4 — Voice add
- `SpeechService`: `SFSpeechRecognizer(locale:)` with on-device recognition when supported, `AVAudioEngine`, live partial transcript, stop → chips. Locales `ar-SA`, `ar-AE`, `tr-TR`, `en-US`, plus the member's own.
- On iOS 26+, use `SpeechAnalyzer`/`SpeechTranscriber` when the locale is supported and `speech_analyzer_enabled` is on.
- Cloud fallback: record AAC (`audio/mp4`, ≤ 15 s) → `transcribeAudio`.
- Done when: `docs/test-voice-ios.md` covers Arabic, Turkish and English phrases from the fixtures, and unit tests cover transcript → chips.

### I5 — Shopping Mode
- Entry points: list "Start shopping", the arrival notification, Live Activity taps, `{URL_SCHEME}://shop`.
- Large rows in category order, haptics, "couldn't find" → `missing`, `isIdleTimerDisabled` while shopping, fully offline.
- "Done" → `updateTrip(done)` → summary with "Send the rest" via `ShareLink`.
- Done when: XCUITests cover tick, undo, missing and finish, including offline.

### I6 — "I'm going", notifications, inline reply
- "I'm going" sheet: nearest five stores from `nearbyStores` (or chain chips without location), free-text store, last-call 0/5/10/15 min → `startTrip(status: heading)`.
- Notification categories per CONTRACT §5.1: `TRIP_HEADING` and `TRIP_ARRIVED` with `UNTextInputNotificationAction` `ADD_ITEM`; `ITEM_MISSING`; local `AUTO_ARRIVED` and `AUTO_LEFT`. The delegate handles replies in the background: local split → write with `addedVia: notification_reply`.
- FCM `Messaging` with APNs token mapping; silent `list_changed` pushes reload widget timelines.
- Done when: unit tests cover the handlers; a manual checklist covers a reply from the lock screen showing up on another phone within 5 s.

### I7 — Live Activity and Dynamic Island
- `ShoppingAttributes` and `ContentState` exactly as CONTRACT §5.2. `lastCallUntil` is `Double?` Unix seconds — do not use `Date` in `ContentState`.
- Presentations: Lock Screen (store, progress, next 3 items, last-call countdown with `Text(timerInterval:)`), Dynamic Island compact, minimal and expanded. Buttons: `CheckNextItemIntent` and `FinishTripIntent` (`LiveActivityIntent`, run in the app process, write with the SDK).
- Start locally with `pushType: .token` when the user starts a trip in the app and send each activity push token with `registerLiveActivityToken`; auto-detected trips arrive by push-to-start from the backend. Update locally while running; end on Done.
- Put sample start/update/end payloads in `docs/live-activity-payloads/` and test them with `xcrun simctl push`.
- Done when: previews of every presentation in ar/tr/en are committed and the simulated pushes render correctly.

### I8 — Store detection
- Settings toggle → "While Using" → rationale → `requestAlwaysAuthorization()`; without Always, the manual "I'm shopping" flow.
- `StoreMonitor` (actor) per ARCHITECTURE §5.2 and §5.3: one `CLMonitor` with the nearest 19 stores (150 m, identifiers `store:<storeId>`) plus a 3 km `refresh` circle; rebuild with `nearbyStores` on refresh exit and on significant location changes.
- On entry: `CMMotionActivityManager` query for the last 3 minutes; skip if automotive → rules (on, ≥ 1 open item, not muted, 3 h cooldown) → local `AUTO_ARRIVED` → `startTrip(status: shopping, auto: true)`; the backend starts the Live Activity by push. On exit during an auto trip → `AUTO_LEFT`.
- Settings: muted stores, "add this store". Debug-only screen: monitored conditions and a "simulate arrival" button. A GPX file for Xcode location simulation in `docs/`.
- Done when: unit tests cover store selection and the rules, and the GPX walkthrough passes.

### I9 — Widgets and Controls
- `ListWidget` (small, medium, large) with `AppIntentConfiguration` to pick a list; rows with `Button(intent: ToggleItemIntent(...))`; + opens `{URL_SCHEME}://add?listId=…&mode=voice`; trip header during shopping.
- Timeline provider: snapshot first; when the system asks for a timeline, also fetch fresh items through `FirestoreREST` with the shared ID token; policy `.after(15 min)`.
- `ToggleItemIntent` write path per ARCHITECTURE §7.4: optimistic snapshot → `PendingOps` → Firestore REST `documents:commit` with `REQUEST_TIME` transforms → dequeue → reload. The app drains `PendingOps` on launch.
- Lock Screen widgets: `accessoryCircular`, `accessoryRectangular`, `accessoryInline`.
- iOS 18+: `QuickAddControl` (`ControlWidgetButton` → `OpenQuickAddIntent` with `openAppWhenRun = true`) and `StartShoppingControl`, usable from Control Center, the Lock Screen and the Action button.
- Done when: ticking on a widget shows up on another device within 10 s; previews of every family in ar/tr/en are committed.

### I10 — App Intents and Siri
